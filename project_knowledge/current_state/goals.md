# Current research goals

ProjectOS investigates how a source-grounded and correctable Project Re-entry Brief can help creative students reconstruct project state and decide what to do next after an interruption.

The current goals are to:

1. Organise project records into six questions about intention, changes, current and superseded directions, feedback, unresolved tensions and possible next action.
2. Make the evidence behind a generated interpretation inspectable, without presenting semantic similarity as factual confidence.
3. Let users confirm, correct or reject reconstructed states while retaining the original records and review history.
4. Evaluate clarity, evidence use, perceived control and review effort through a formative study.

## Present scope

**7 October update — assigned-project readiness:** the implementation now separates a one-section Echo Field tutorial from each participant's assigned project. Researchers validate local project packs and prepare six summaries before serving a session bound to one code. The proposed formal study concerns the participant's own creative project after at least one to two weeks away. This is a scope proposal requiring supervisor / ethics confirmation and revised information/consent materials; it does not change the research question or establish study outcomes. See the [data protocol draft](../feedback/user_testing/iteration_1/participant_owned_project_data_protocol_draft.md). The paragraphs below retain the 4 October scope for provenance.

The implemented prototype is a local Streamlit application using one prepared Echo Field archive. Retrieval runs locally; summary generation sends selected excerpts to the OpenAI API. The prototype does not yet establish improvements in creativity, productivity or long-term project outcomes.

The proposed first study is a simulated return to a prepared project. It can investigate the interaction, but cannot establish the benefit of returning to a participant's own project after a real interruption.
