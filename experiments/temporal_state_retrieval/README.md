# Current production retrieval baseline

This independent evaluator measures the frozen [Phase 1 protocol](../../project_knowledge/process/experiments/temporal_state_retrieval/experiment_protocol.md). It does not change the ProjectOS application, introduce a retrieval algorithm, generate summaries or assess participant projects.

## Reuse and boundaries

`baseline.py` calls `document_loader.load_documents`, `chunking.create_chunks`, `retrieval.SemanticRetriever.retrieve`, `reentry_brief.get_section_queries`, `select_evidence`, `retrieve_diverse_evidence` and `create_excerpt`. A path-like adapter enumerates only the frozen view's eligible records. The loader still sorts, reads and categorises them. A counted model wrapper shares one offline model instance across four independent corpus indices; the production constructor still encodes each corpus once, and its retrieval method still normalises embeddings, computes cosine scores and uses its original NumPy tie ordering.

RetrievalRequest carries only view identity, source root, eligible filenames and section ID. Gold questions, passages, labels and roles cannot enter retrieval inputs. Diagnostic cases evaluate the unchanged section-query output in their frozen view. There is no search with a more specific diagnostic question.

The command-line entry point accepts separate private-label, private-manifest, new ignored private-output, existing local-model-snapshot and public-output locations. It refuses missing local weights, an existing private run directory or a private destination that Git does not ignore. Offline flags and a process-local boundary guard prohibit network requests and reads of real participant materials, reviews, summary caches and assignments. No credentials are retained by the child process. Synthetic unit fixtures do not load a model.

## Prespecified scoring implementation

The actual selected pair occupies ranks 1–2. The remaining category-eligible chunks are appended by maximum cosine across the unchanged section queries, with chunk ID breaking tail ties, as specified before baseline execution. This tail is evaluation-only; it cannot replace a production selection.

Full source-located quotes must match after whitespace normalisation only. Token offsets are reconstructed from the original text and verified against every production chunk. An assertion split across chunks does not become a match by concatenating fragments. A required heading or date must also be visible within the cutoff; no gold-derived heading metadata is attached. Overlapping windows count a passage once. Acceptable roles and temporal compatibility are evaluated only after retrieval.

Temporal attribution uses frozen annotations only. A selected item is fully judged only if its visible non-whitespace tokens are covered by complete, unambiguous annotated assertions. Otherwise it is unjudged, even if one assertion matches. Unknown temporal attribution is excluded separately when the item is otherwise fully judged. This conservative coverage check avoids assigning a temporal status to unannotated text; it does not create new labels. Accepted historical direction partners are exempt from false-current exposure. Known excluded exposure is separately retained as a lower bound across all current-claim cases; unjudged cases are never safe negatives.

The two tiers have separate numerators, denominators and exclusions. Role coverage is a macro mean of per-case role fractions, with raw covered/required role totals also reported. Pair coverage requires a frozen complete accepted pair. Applicability excludes unclear cases; scoped explicit-negative cases use closure evidence, never the absence of files. Missing-versus-inapplicable contingencies give unjudged precedence. Support, applicability and abstention classification accuracy are not measurable at retrieval-only baseline.

## Timing and interpretation

Before execution, timing is fixed at one first query, one warm-up and 30 warm repetitions for each unique view/section. Repetitions cycle through requests in sorted round-robin order. There is only one arm in this phase, so no alternative arm is interleaved. Timers include query encoding, ranking, production selection and production excerpts; offset mapping and scoring are outside the timer. Model loading, corpus preparation and document encoding are separate. Reused requests do not receive repeated timing weight merely because several diagnostic cases inspect them.

The final reporting audit distinguishes two scopes. The distinct-request distribution counts actual timed requests: production has 18 requests and 540 warm measurements; diagnostic has 14 requests and 420 warm measurements covering all 16 cases. Two diagnostic pairs share a view/section request. This has no relationship to excluding insufficient cases from positive-gold accuracy metrics: both insufficient diagnostics have first-query and 30 warm measurements. A separate all-case-weighted distribution reports 16 first-query contributions and 480 warm contributions for diagnostics, reusing saved measurements for shared requests. Those contributions are not new independent observations. Production has no within-tier duplicates, so its two timing scopes coincide.

The 34 case-to-request associations are audited without rerunning retrieval. Four views each have six section requests, giving 24 unique requests. Each execution encodes two query texts afresh. Thus query encode calls and query texts both equal `24 * 2 * (1 + 1 + 30) = 1536`: 48 first-run encodes, 48 warm-up encodes and 1,440 timed-warm encodes. Tier attribution is `1152 production + 896 diagnostic - 512 shared = 1536`; tier counts must not be summed without subtracting shared requests. Cases reuse results and timing records, not cached query embeddings across repetitions. Four document encode calls contain `12 + 49 + 5 + 8 = 74` texts; total encode calls are `4 + 1536 = 1540`, and total encoded texts are `74 + 1536 = 1610`. One offline model instance is shared across all four indices.

Public output includes aggregate project/section breakdowns and public demonstration/synthetic cases only. Researcher-archive case identities, passage matches, excerpts and per-request traces remain in the ignored private output. These single-researcher gold labels have no inter-rater agreement estimate. Retrieval evidence coverage is neither exhaustive project reconstruction nor summary accuracy. Unjudged outputs must be resolved before any definitive comparison with a future method; this baseline does not authorise that next phase.

## Import and regression validation

Importing this evaluator does not run an experiment, load a model, write files or change the working directory or environment. Production imports temporarily resolve the existing source directory and restore `sys.path` on exit. The new test module likewise restores its bootstrap path through a monkeypatch context.

The final follow-up passed both baseline/evidence-guidance orders (52 tests each), the 129 existing tests, and two consecutive complete suites (157 tests each) in separate temporary workspaces. Two added regression tests cover import boundaries and path restoration. The original temporary-cache failure did not recur; a filesystem path-length probe provides a possible explanation, but its original root cause remains unconfirmed. See the [validation report](../../outputs/test_results/temporal_state_retrieval_baseline/baseline_report.md) for the complete matrix, limitations and preserved initial failure. No baseline or model work was repeated during this follow-up.
